# Web 指挥台实现计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 新增 `apps/web`（Vite + React 纯客户端）：以流水线形式可视化五个角色，实时显示各角色的文本输出，提供需求输入、方案选择、修改意见、继续、重试、取消，以及角色分配（agent / 模型 / 强度）与认证设置。补齐 spec 第 7 节的组件测试与一次 Playwright 端到端主线。

**Architecture:** `web` 只依赖 `@agentteam/protocol`，所有状态都来自 `GET /api/state` 与 `GET /api/events`（SSE），所有操作都经现有 HTTP 接口；页面不做业务判断，只做展示与转发。SSE 断线由浏览器 `EventSource` 自动重连（服务端按 `Last-Event-ID` 续传），客户端按 `seq` 去重；流程推进时补拉一次 `GET /api/state` 对齐。视图按用途拆目录：`pipeline/`（流水线）、`transcript/`（对话记录）、`role-panel/`（角色输出流）、`composer/`（输入区）、`settings/`（角色分配与认证），共享一个 `store.jsx` 中的外部 Store。

**Tech Stack:** Vite 8.3.5、React 19.3.1、@vitejs/plugin-react 6.2.0、vitest 5.0.5、jsdom 28.1.0、@testing-library/react 16.3.3、@testing-library/dom 10.4.2、@testing-library/user-event 14.6.8、@testing-library/jest-dom 6.10.0、@playwright/test 1.64.1。纯 CSS，不引入状态管理库。

**Spec:** `docs/superpowers/specs/2026-10-30-web-console-design.md`。前置计划：`docs/superpowers/plans/2026-11-02-engine-layer.md`、`docs/superpowers/plans/2026-11-02-server.md`（均已完成）。

## 视觉规范

`main.css` 里定义这些 token，各视图只引用变量：

| Token | 值 | 用途 |
| --- | --- | --- |
| `--bg` | `#0E1316` | 页面底色 |
| `--bg-raised` | `#162024` | 卡片、输入框、输出流底色 |
| `--bg-hover` | `#1E2A2F` | 悬停 |
| `--line` | `#26343A` | 分隔线 |
| `--text` | `#E8EEE6` | 主文字 |
| `--muted` | `#93A19A` | 次要文字、空态说明 |
| `--faint` | `#5C6B63` | 禁用文字 |
| `--brand` | `#5EB6A6` | 进行中、已连接、主按钮 |
| `--brand-text` | `#0B1712` | 品牌底色上的文字 |
| `--error` | `#C77E74` | 失败、错误 |
| `--done` | `#7FA8C0` | 已完成（弱于进行中） |
| `--focus-ring` | `#E0EC8A` | 键盘焦点环 |

原则：

- 唯一记忆点：**流水线是五个角色各一行的"灯 + 名字 + 状态"，进行中的那盏灯是青绿色**。其余元素保持安静。
- 字体单一栈：`ui-monospace, SFMono-Regular, Consolas, "Courier New", monospace`，全程等宽，贴合"命令行"气质。
- 结构用分隔线，不用投影和大圆角；圆角统一 `3px`。
- 层次：左栏是主角（对话记录 → 输出流 → 输入区），右栏是流水线与设置。
- 键盘焦点：`:focus-visible` 用 `2px` 的 `--focus-ring`；`prefers-reduced-motion: reduce` 下关闭过渡。

- [ ] **Step 7: 写 `src/text.js`**

```js
export const ROLE_ORDER = ['req-analyst', 'architect', 'frontend-dev', 'backend-dev', 'qa'];

export const ROLE_NAMES = {
  'req-analyst': '需求与原型',
  architect: '架构师',
  'frontend-dev': '前端开发',
  'backend-dev': '后端开发',
  qa: '测试',
};

export const STAGE_TEXT = {
  idle: '等待需求',
  arch_review: '等待选择方案',
  delivered: '已交付',
  closed: '已取消',
  failed: '步骤失败',
  paused: '已暂停',
};

export const STATUS_TEXT = {
  idle: '等待',
  running: '运行中',
  done: '完成',
  failed: '失败',
  interrupted: '已中断，可重试',
};

export const EMPTY_VIEW = {
  roleState: {},
  outputs: {},
  files: {},
  messages: [],
  lastEvent: null,
};

// 每个角色当前的终态：按事件顺序记录"最后一次见到的事件"，不用计数推导。
// 用计数会在重试时出错：失败一次后重试成功（started 2、failed 1、finished 1）会被判为失败。
export const ROLE_EVENTS = {
  'role.started': 'running',
  'role.finished': 'done',
  'role.failed': 'failed',
};

// running 为 false，但该角色的最后一条事件是 started：
// 服务在角色运行中崩溃或重启后留下的状态（backlog B-007），显示为"已中断，可重试"。
export function isInterrupted({ running, role, roleState }) {
  return !running && roleState[role] === 'running';
}

// 角色状态：最后一次事件决定状态；没有事件就是 idle。
// 注意：构建阶段（选了方案之后）stage 仍然是 arch_review，因为工作流在最后一步才改 stage；
// 所以"正在跑"必须用 running 判断，不能用 stage。
export function roleStatus({ running, role, roleState }) {
  const last = roleState[role];
  if (!last) return 'idle';
  if (last === 'running' && !running) return 'interrupted';
  return last;
}

// 新一轮需求分析开始：req-analyst 重新开跑，且当前没有任何角色在运行。
// 只有这时才清空角色状态——选方案、给意见、继续、重试都会让"需求与原型/架构师"的
// 完成标记不该丢（流水线的意义就是保留进度）。上一轮交付后残留的"完成"在这里被清掉。
function startsNewRound(view, event) {
  if (event.type !== 'role.started' || event.role !== 'req-analyst') return false;
  return !Object.values(view.roleState).includes('running');
}

// 事件 → 视图增量。纯函数，不读时钟、不读外部状态，便于测试。
export function reduceEvents(view, event) {
  let roleState = startsNewRound(view, event) ? {} : view.roleState;
  if (event.role && ROLE_EVENTS[event.type]) {
    roleState = { ...roleState, [event.role]: ROLE_EVENTS[event.type] };
  }

  let outputs = view.outputs;
  if (event.type === 'role.output' && event.role) {
    outputs = { ...outputs, [event.role]: [...(outputs[event.role] ?? []), event.chunk] };
  }

  let files = view.files;
  if (event.type === 'role.files' && event.role) {
    files = { ...files, [event.role]: [...(files[event.role] ?? []), ...event.files] };
  }

  const messages = event.type === 'message' ? [...view.messages, event] : view.messages;

  return { roleState, outputs, files, messages, lastEvent: event };
}
```

`reduceEvents` 同时承担输出与产物收集：事件是逐条喂进来的，所以不会像"只读最后一条事件"那样丢片段。

- [ ] **Step 8: 写 `src/text.test.js`（先写测试，再核对 Step 7 的实现）**

```js
import { test, expect } from 'vitest';
import { isInterrupted, roleStatus, reduceEvents, EMPTY_VIEW } from './text.js';

function apply(events) {
  return events.reduce((view, event) => reduceEvents(view, event), EMPTY_VIEW);
}

test('role.output 逐条累积，不丢片段', () => {
  const view = apply([
    { seq: 1, type: 'role.output', role: 'architect', chunk: '第一段' },
    { seq: 2, type: 'role.output', role: 'architect', chunk: '第二段' },
  ]);
  expect(view.outputs.architect).toEqual(['第一段', '第二段']);
});

test('role.files 与 message 分别累积', () => {
  const view = apply([
    { seq: 1, type: 'role.files', role: 'backend-dev', files: ['docs/backend/IMPL-001.md'] },
    { seq: 2, type: 'role.files', role: 'backend-dev', files: ['src/app.js'] },
    { seq: 3, type: 'message', from: 'user', text: '做个登录' },
    { seq: 4, type: 'message', from: 'team', text: '已交付' },
  ]);
  expect(view.files['backend-dev']).toEqual(['docs/backend/IMPL-001.md', 'src/app.js']);
  expect(view.messages.map((m) => m.from)).toEqual(['user', 'team']);
});
```

```js
// 相对路径：开发时经 vite.config.js 的 /api 代理到 127.0.0.1:4317，
// 生产时由 packages/server 同源托管。
const BASE = '/api';

export function apiErrorText(status, body) {
  if (body?.error) return body.error;
  if (status === 400) return '请求不合法';
  if (status === 403) return '不允许访问';
  if (status === 404) return '接口不存在';
  if (status === 409) return '已有流程在运行';
  if (status === 413) return '请求内容过大';
  return '服务出错';
}

export function createApi(fetchImpl) {
  async function request(path, options = {}) {
    // 调用时再取 fetch：模块加载后测试会用 vi.stubGlobal 替换全局 fetch，这里必须能拿到替身。
    const doFetch = fetchImpl ?? globalThis.fetch;
    let res;
    try {
      res = await doFetch(`${BASE}${path}`, {
        headers: { 'Content-Type': 'application/json' },
        ...options,
      });
    } catch {
      return { ok: false, error: '无法连接服务' };
    }
    const text = await res.text();
    let body = null;
    try {
      body = text ? JSON.parse(text) : null;
    } catch {
      // 非 JSON 响应：按状态码给固定文案
    }
    if (!res.ok) return { ok: false, error: apiErrorText(res.status, body) };
    return { ok: true, data: body };
  }

  return {
    fetchState: () => request('/state'),
    fetchRoles: () => request('/roles'),
    putRoles: (assignments) => request('/roles', { method: 'PUT', body: JSON.stringify({ assignments }) }),
    fetchAgents: () => request('/agents'),
    postMessage: (text) => request('/message', { method: 'POST', body: JSON.stringify({ text }) }),
    postPause: () => request('/pause', { method: 'POST' }),
    postCancel: () => request('/cancel', { method: 'POST' }),
    postAuth: (agentId, body) => request(`/auth/${agentId}`, { method: 'POST', body: JSON.stringify(body) }),
  };
}

const defaultApi = createApi();

export const {
  fetchState, fetchRoles, putRoles, fetchAgents, postMessage, postPause, postCancel, postAuth,
} = defaultApi;
```

```jsx
import { createContext, useContext, useEffect, useSyncExternalStore } from 'react';
import { fetchState as apiFetchState } from './api.js';
import { EMPTY_VIEW, reduceEvents } from './text.js';

// 流程推进的事件到达后补拉一次 /api/state：stage 与 running 以磁盘状态为准。
// role.started / role.output / role.files 不影响 stage 与 running，不需要重拉。
const RESYNC_TYPES = new Set(['stage.changed', 'role.finished', 'role.failed', 'message']);
// 两个原因让刷新必须延迟且合并：
// 1) stage.changed 是这一轮的收尾事件，但服务端发出它之后才把 running 置回 false
//    （session.send 的 finally）。立刻刷新会读到 running: true，而之后再没有事件来纠正，
//    发送按钮会永久消失。
// 2) 首次连接会重放全部历史，每条 message 都触发一次刷新就是几十个并发请求。
const SETTLE_MS = 200;

export function openEventSource({ onOpen, onError, onEvent }) {
  // 不带 after 参数：服务端会优先用 after 查询参数，那样浏览器自动重连时永远从同一个
  // 旧序号重放，会重复推事件。不传时服务端按 Last-Event-ID 续传，首次连接从 0 全量重放。
  const source = new EventSource('/api/events');
  source.onopen = () => onOpen();
  source.onerror = () => onError();
  source.onmessage = (message) => {
    let event = null;
    try {
      event = JSON.parse(message.data);
    } catch {
      return; // 损坏的一行：跳过，不打断整条流
    }
    onEvent(event);
  };
  return () => source.close();
}

export function createStore({ fetchState = apiFetchState, createStream = openEventSource } = {}) {
  let snapshot = {
    status: 'connecting',
    connectError: null,
    state: { stage: 'idle', running: false, lastSeq: 0 },
    ...EMPTY_VIEW,
  };
  const listeners = new Set();
  let disconnect = null;
  let lastSeen = 0;
  let resyncTimer = null;

  const set = (patch) => {
    snapshot = { ...snapshot, ...patch };
    for (const listener of [...listeners]) listener();
  };

  const store = {
    snapshot: () => snapshot,
    subscribe(listener) {
      listeners.add(listener);
      return () => listeners.delete(listener);
    },
    async refresh() {
      const result = await fetchState();
      if (result.ok) set({ state: result.data, connectError: null });
      else set({ connectError: result.error });
      return result;
    },
    applyEvents(events) {
      set(events.reduce((view, event) => ({ ...view, ...reduceEvents(view, event) }), snapshot));
    },
    connect() {
      if (disconnect) return disconnect;
      // 合并刷新：200ms 内的多个触发只拉一次。
      const scheduleResync = () => {
        if (resyncTimer) return;
        resyncTimer = setTimeout(() => {
          resyncTimer = null;
          store.refresh();
        }, SETTLE_MS);
      };
      const close = createStream({
        onOpen: () => set({ status: 'live', connectError: null }),
        onError: () => set({ status: 'error', connectError: '连接中断，正在重连…' }),
        onEvent: (event) => {
          // 首次连接会全量重放，重连时服务端可能重发边界事件：按 seq 去重。
          if (!Number.isInteger(event?.seq) || event.seq <= lastSeen) return;
          lastSeen = event.seq;
          store.applyEvents([event]);
          if (RESYNC_TYPES.has(event.type)) scheduleResync();
        },
      });
      disconnect = () => {
        close();
        if (resyncTimer) {
          clearTimeout(resyncTimer);
          resyncTimer = null;
        }
        disconnect = null;
      };
      return disconnect;
    },
  };
  return store;
}

const StoreContext = createContext(null);

export function StoreProvider({ store, children }) {
  return <StoreContext.Provider value={store}>{children}</StoreContext.Provider>;
}

export function useStore() {
  const store = useContext(StoreContext);
  if (!store) throw new Error('useStore 必须在 StoreProvider 内使用');
  return useSyncExternalStore(store.subscribe, store.snapshot);
}

export function useEventStream(store) {
  useEffect(() => {
    store.refresh();
    return store.connect();
  }, [store]);
  const { status, connectError } = useStore();
  return { status, connectError };
}
```

- [ ] **Step 2: 写 `Composer.jsx`**

```jsx
import { useState } from 'react';
import { useStore } from '../store.jsx';
import { postMessage, postPause, postCancel } from '../api.js';
import { STAGE_TEXT } from '../text.js';

const CAN_SEND = new Set(['idle', 'arch_review', 'failed', 'paused', 'delivered', 'closed']);

export default function Composer() {
  const { state } = useStore();
  const [text, setText] = useState('');
  const [error, setError] = useState(null);
  const { stage, running } = state;

  async function send(value) {
    const trimmed = value.trim();
    if (!trimmed) return;
    const result = await postMessage(trimmed);
    if (!result.ok) {
      setError(result.error);
      return;
    }
    setError(null);
    setText('');
  }

  async function pause() {
    const result = await postPause();
    setError(result.ok ? null : result.error);
  }

  async function cancel() {
    const result = await postCancel();
    setError(result.ok ? null : result.error);
  }

  const placeholder =
    stage === 'failed'
      ? '修正后回复"重试"'
      : stage === 'paused'
        ? '回复"继续"接着做'
        : stage === 'arch_review'
          ? '输入方案字母，或写讨论意见'
          : stage === 'delivered' || stage === 'closed'
            ? '先发送"新需求"，再写下一条需求'
            : '输入需求';

  return (
    <section className="composer" aria-label="输入区">
      <p className="composer-stage">{STAGE_TEXT[stage] ?? stage}</p>
      {error && <p className="composer-error" role="alert">{error}</p>}
      <div className="composer-row">
        <textarea
          aria-label="需求或意见输入"
          placeholder={placeholder}
          value={text}
          onChange={(event) => setText(event.target.value)}
          onKeyDown={(event) => {
            // Enter 发送，Shift+Enter 换行；运行中不发送。
            if (event.key === 'Enter' && !event.shiftKey) {
              event.preventDefault();
              if (!running && CAN_SEND.has(stage)) send(text);
            }
          }}
        />
        <div className="composer-actions">
          {!running && CAN_SEND.has(stage) && (
            <button type="button" className="primary" onClick={() => send(text)} disabled={!text.trim()}>
              发送
            </button>
          )}
          {!running && stage === 'failed' && (
            <button type="button" onClick={() => send('重试')}>重试</button>
          )}
          {!running && stage === 'paused' && (
            <button type="button" onClick={() => send('继续')}>继续</button>
          )}
          {running && (
            <>
              <button type="button" onClick={pause}>暂停</button>
              <button type="button" onClick={cancel}>取消</button>
            </>
          )}
        </div>
      </div>
    </section>
  );
}
```

```jsx
import { useEffect, useState } from 'react';
import { useStore } from '../store.jsx';
import { fetchRoles, putRoles, fetchAgents, postAuth } from '../api.js';
import { ROLE_ORDER, ROLE_NAMES } from '../text.js';

const OTHER_MODEL = '__other';

export default function Settings() {
  const { state } = useStore();
  const locked = state.running;
  const [roles, setRoles] = useState(null);
  const [agents, setAgents] = useState(null);
  const [editing, setEditing] = useState(null);
  const [draft, setDraft] = useState({ agent: 'claude', model: '', effort: '' });
  const [customModel, setCustomModel] = useState(false);
  const [keyFor, setKeyFor] = useState(null);
  const [apiKey, setApiKey] = useState('');
  const [error, setError] = useState(null);
  const [notice, setNotice] = useState(null);

  async function load() {
    const [rolesResult, agentsResult] = await Promise.all([fetchRoles(), fetchAgents()]);
    if (rolesResult.ok) setRoles(rolesResult.data);
    else setError(rolesResult.error);
    if (agentsResult.ok) setAgents(agentsResult.data);
    else setError(agentsResult.error);
  }

  useEffect(() => {
    load();
  }, []);

  const agentInfo = agents?.find((agent) => agent.id === draft.agent);

  function startEdit(role) {
    const current = roles?.[role] ?? { agent: 'claude', model: null, effort: null };
    const models = agents?.find((agent) => agent.id === current.agent)?.models ?? [];
    setEditing(role);
    setDraft({ agent: current.agent, model: current.model ?? '', effort: current.effort ?? '' });
    setCustomModel(Boolean(current.model) && !models.includes(current.model));
    setError(null);
    setNotice(null);
  }

  async function saveRole() {
    const result = await putRoles({
      [editing]: {
        agent: draft.agent,
        model: draft.model.trim() ? draft.model.trim() : null,
        effort: draft.effort || null,
      },
    });
    if (!result.ok) {
      setError(result.error);
      return;
    }
    setEditing(null);
    setNotice('已保存角色分配');
    await load();
  }

  async function saveKey(agentId) {
    const result = await postAuth(agentId, { method: 'api', apiKey });
    if (!result.ok) {
      setError(result.error);
      return;
    }
    // key 只提交一次，成功后立刻清空，不再留在页面状态里。
    setApiKey('');
    setKeyFor(null);
    setNotice(`${agentId} 已保存 API key`);
    await load();
  }

  async function confirmLogin(agentId) {
    const result = await postAuth(agentId, { method: 'confirm' });
    if (!result.ok) {
      setError(result.error);
      return;
    }
    setNotice(`${agentId} 已标记为已登录`);
    await load();
  }

  if (!roles || !agents) {
    return (
      <section className="settings" aria-label="角色分配与认证">
        <p className="settings-empty">{error ?? '正在读取角色分配…'}</p>
      </section>
    );
  }

  return (
    <section className="settings" aria-label="角色分配与认证">
      <h2>角色分配</h2>
      {locked && <p className="settings-note">流程运行中，不能修改角色分配。</p>}
      {error && <p className="settings-error" role="alert">{error}</p>}
      {notice && <p className="settings-notice">{notice}</p>}
      <ul className="settings-roles">
        {ROLE_ORDER.map((role) => {
          const assigned = roles[role];
          return (
            <li key={role} className="settings-role">
              <div className="settings-role-line">
                <span className="settings-role-name">{ROLE_NAMES[role]}</span>
                <span className="settings-role-value">
                  {assigned.agent}
                  {assigned.model ? ` / ${assigned.model}` : ''}
                  {assigned.effort ? ` / ${assigned.effort}` : ''}
                </span>
                <button type="button" onClick={() => startEdit(role)} disabled={locked}>修改</button>
              </div>
              {editing === role && (
                <div className="settings-editor">
                  <label>
                    agent
                    <select
                      aria-label="agent"
                      value={draft.agent}
                      onChange={(event) => {
                        setDraft({ agent: event.target.value, model: '', effort: '' });
                        setCustomModel(false);
                      }}
                    >
                      {agents.map((agent) => (
                        <option key={agent.id} value={agent.id}>{agent.name}</option>
                      ))}
                    </select>
                  </label>
                  <label>
                    模型
                    {customModel ? (
                      <input
                        aria-label="模型"
                        value={draft.model}
                        onChange={(event) => setDraft({ ...draft, model: event.target.value })}
                        placeholder="模型名"
                      />
                    ) : (
                      <select
                        aria-label="模型"
                        value={draft.model}
                        onChange={(event) => {
                          if (event.target.value === OTHER_MODEL) {
                            setCustomModel(true);
                            setDraft({ ...draft, model: '' });
                          } else {
                            setDraft({ ...draft, model: event.target.value });
                          }
                        }}
                      >
                        <option value="">agent 默认</option>
                        {(agentInfo?.models ?? []).map((model) => (
                          <option key={model} value={model}>{model}</option>
                        ))}
                        <option value={OTHER_MODEL}>其他…</option>
                      </select>
                    )}
                  </label>
                  {(agentInfo?.efforts ?? []).length > 0 && (
                    <label>
                      强度
                      <select
                        aria-label="强度"
                        value={draft.effort}
                        onChange={(event) => setDraft({ ...draft, effort: event.target.value })}
                      >
                        <option value="">agent 默认</option>
                        {agentInfo.efforts.map((effort) => (
                          <option key={effort} value={effort}>{effort}</option>
                        ))}
                      </select>
                    </label>
                  )}
                  <div className="settings-editor-actions">
                    <button type="button" className="primary" onClick={saveRole}>保存</button>
                    <button type="button" onClick={() => setEditing(null)}>取消</button>
                  </div>
                </div>
              )}
            </li>
          );
        })}
      </ul>

      <h2>认证</h2>
      <ul className="settings-agents">
        {agents.map((agent) => (
          <li key={agent.id} className="settings-agent">
            <div className="settings-agent-line">
              <span>{agent.name}</span>
              <span className={agent.authenticated ? 'auth-ok' : 'auth-no'}>
                {agent.authenticated ? '已认证' : '未认证'}
              </span>
              {agent.kind === 'api'
                ? keyFor !== agent.id && (
                  <button type="button" onClick={() => { setKeyFor(agent.id); setApiKey(''); setError(null); }}>
                    填写 API key
                  </button>
                )
                : (
                  <button type="button" onClick={() => confirmLogin(agent.id)}>确认已登录</button>
                )}
            </div>
            {agent.kind === 'api' && keyFor === agent.id && (
              <div className="settings-key">
                <input
                  type="password"
                  aria-label={`${agent.name} 的 API key`}
                  autoComplete="off"
                  value={apiKey}
                  onChange={(event) => setApiKey(event.target.value)}
                />
                <button type="button" className="primary" onClick={() => saveKey(agent.id)}>保存 key</button>
                <button type="button" onClick={() => { setKeyFor(null); setApiKey(''); }}>取消</button>
              </div>
            )}
            {agent.kind !== 'api' && (
              <p className="settings-hint">先在终端完成该 agent 的登录，再点"确认已登录"。</p>
            )}
          </li>
        ))}
      </ul>
    </section>
  );
}
```

- [ ] **Step 1: 写 `scripts/fake-server.js`**

```js
import { existsSync } from 'node:fs';
import { mkdir, mkdtemp, readFile, writeFile } from 'node:fs/promises';
import { tmpdir } from 'node:os';
import { join } from 'node:path';
import { fileURLToPath } from 'node:url';
import { startServer } from '../../../packages/server/src/serve.js';
import { createSession } from '../../../packages/core/src/session.js';

const PORT = 4399;
const WEB_DIR = fileURLToPath(new URL('../dist', import.meta.url));
// startServer 在 webDir 不存在时会静默跳过静态托管（页面打不开但接口正常），
// 所以这里先明确失败，把"忘了构建"变成一条清楚的错误。
if (!existsSync(join(WEB_DIR, 'index.html'))) {
  console.error(`找不到 ${WEB_DIR}/index.html，请先运行 npm run build -w apps/web`);
  process.exit(1);
}

// 假的派发：不调用任何真实 agent。与 packages/core/test/session.test.js 的 fakeDispatch 同构：
// 按任务卡"交付："段写文件；另外写一个应用代码文件，满足工作流"实现角色必须改动应用代码"的判定。
// 每个角色停顿 ROLE_DELAY_MS：真实角色要跑几分钟，这里留一点时间让界面能显示出进度，
// 也让"边跑边刷新的渲染逻辑"真的被执行到（否则所有事件会在同一帧里到达）。
// 注意：e2e 不断言"运行中"这种瞬时状态，只断言会持久存在的内容。
const ROLE_DELAY_MS = 300;

async function fakeDispatch({ root, taskId, role, onOutput }) {
  onOutput?.(`${role} 工作中\n`);
  await new Promise((resolve) => setTimeout(resolve, ROLE_DELAY_MS));
  const card = await readFile(join(root, 'team', 'tasks', `${taskId}.md`), 'utf8');
  const lines = card.split('\n');
  const outputs = lines
    .slice(lines.indexOf('交付：') + 1)
    .filter((line) => line.startsWith('- '))
    .map((line) => line.slice(2));

  for (const output of outputs) {
    const full = join(root, output);
    await mkdir(join(full, '..'), { recursive: true });
    const body = output.endsWith('-summary.md')
      ? '## 方案 A：Node + React\n\n## 方案 B：Go + Vue\n'
      : `# ${output}\n`;
    await writeFile(full, body, 'utf8');
  }

  const changed = [...outputs];
  if (role === 'backend-dev' || role === 'frontend-dev') {
    const code = join(root, 'src', `${role}.js`);
    await mkdir(join(root, 'src'), { recursive: true });
    await writeFile(code, `// ${role}\n`, 'utf8');
    changed.push(`src/${role}.js`);
  }

  return { ok: true, text: '', changed, log: null };
}

const root = await mkdtemp(join(tmpdir(), 'agentteam-e2e-'));
const session = await createSession({ root, dispatch: fakeDispatch });
const server = await startServer({
  root,
  port: PORT,
  credentialsFile: join(root, 'credentials.json'),
  webDir: WEB_DIR,
});

console.log(`fake-server 已启动：${server.url}（项目目录 ${root}）`);

let stopping = false;
async function stop() {
  if (stopping) return;
  stopping = true;
  await server.close();
  process.exit(0);
}
process.on('SIGTERM', stop);
process.on('SIGINT', stop);
```

```js
test('主线：从提需求到交付', async ({ page }) => {
  await page.goto('/');

  // 空态：阶段"等待需求"，五个角色都在
  await expect(page.getByRole('heading', { name: '等待需求' })).toBeVisible();
```

**4. 计划内裁决（Ruling 记录）**

- **SSE 不带 `after` 查询参数**：服务端 `serveEvents` 的取值顺序是 `after` 查询参数优先于 `Last-Event-ID`；若把 `after` 写进 URL，浏览器自动重连会永远从旧序号重放。因此首次连接不带参数（服务端从 0 全量重放），重连靠 `Last-Event-ID` 续传，客户端再按 `seq` 去重兜底。代价：首次连接会重放全部历史事件（项目事件量小，可接受）。
- **按钮用 `running` 而不是 `stage` 判断**：工作流在构建阶段不改变 `stage`（仍是 `arch_review`），只看 `stage` 会把"构建中"误判成"等待选择方案"。代价：`Composer` 需要读 `state.running`。
- **`stage.changed` 之后延迟 200ms 刷新**：服务端先发 `stage.changed`、再把 `running` 置回 false（`session.send` 的 `finally`），立刻刷新会读到 `running: true` 且之后没有事件纠正，发送按钮会永久消失。代价：每轮结束到按钮恢复有 200ms 延迟，用户无感。
- **e2e 固定端口 4399**：`webServer.url` 必须在配置加载时已知，随机端口做不到。代价：端口占用时 e2e 直接失败，需要换端口或结束占用进程。
- **e2e 选方案用"发送字母"**：`Composer` 只发文本，由服务端 `handleMessage` 解析字母与序号；不做方案卡片 UI（YAGNI）。代价：方案需要用户读对话记录后手输字母，第一版可接受。
- **不引入状态管理库**：用 `useSyncExternalStore` + 一个 `createStore` 工厂，满足"运行时依赖只有 protocol + react"的约束。
- **`RolePanel` 只展示，不推导状态**：状态文案由 `Pipeline` 与 `RolePanel` 共用 `roleStatus`，不各写一份。
